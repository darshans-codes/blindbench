# Engineering playbook

Keep the control application modular. Run separate runtimes and credentials where the protocol has separate trust roles. Use typed contracts, migrations, state transitions, timeouts, and replay-safe effects. Keep secrets server-side and participant measurements in the browser. Document residual risk next to each claim.

Work in vertical slices. Before expanding the feature set, prove browser report generation and independent aggregation on a known synthetic histogram. For each accepted slice, record unit, API, integration, and responsive browser evidence in the quality report. Include keyboard use, errors and empty states. Record failed and blocked checks as such.

Use the design tokens in `DESIGN.md`. Evaluate design tools against accessibility, maintainability and the project timebox. Review dependency licenses and security before adoption. Establish a reproducible local launch and rollback path before treating the result as portfolio-ready.

Review the ten adaptive controls in `ENGINEERING_CONTROLS.md` at each milestone. Keep the threat model, runbook, reproducible demo and contribution notes current. Use the specification's fixed acceptance criteria for verification and continue building locally.
